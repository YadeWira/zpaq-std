PJA 0.9.10 (tag v0.9.10, commit 68f25f8), https://github.com/YadeWira/PJA,
from the vendor tarball pja-0.9.10-zpaqstd.tar.gz (sha256
075a65d72219e2b3ad4f64b8240e7df293835ec444ede352bb8821cf72f7f467), copied unmodified.
0.9.10 changes nothing for this plugin but the version in its card (pas/pjacodec.pas) and
VENDOR.md: its change is in PJA's 7-Zip plugin. The 31 codecs, streams, ZPAQL, detect and
lists are 0.9.9's (tarball sha256 41965cdf...), which was in zpaq-std 2.9.0.
For the plugin, 0.3.0 frees each coding thread's model tables when the thread ends
(they leaked, and ran out of memory on 32 bits), and 0.4.0 adds the five z codecs
(pjaz, pjalsz, pjaxz, pjallz, pjalsxz): the ZPAQL of each base codec with zpaq's
level 1 LZ77 expander in front (pas/plugin/lzzpaql.inc). -sa uses one for a group
when it takes fewer bytes; they are never used by themselves. 0.5.1: pjax's detect
measures the big MPOs right (they go to pjax), the detects share one check of the
JPEG, and zpaqstd_threads_v1 (zpaq-std's -t) gives each call threads for its bands.
0.5.2 and 0.5.3 change PJA's command and libpja (a scan cut short is repaired); for
the plugin only pjacodec.pas changes (that repair, and its own check's output cap),
and its codecs write the bytes of 0.5.1. 0.6.0 adds PJA's stream v7: pja7 and pjax7
(and their z, pja7z and pjax7z), a better model with smaller, faster decoders (about
35 KB), which take the place of pja and pjax in -sa; those stay in the plugin, to read
the archives made with them. Stream v7's model is in C (pjav7c.c, pjasysc.c, built by
pas/build_c.sh and linked by fpc). 0.6.2 changes no stream, ZPAQL or codec: on Windows
the plugin takes its memory from the process heap (pas/pjaheap.pas), since FreePascal
3.2.2's own heap, in a DLL, deletes its lock when the thread that loaded the DLL ends,
and zpaq-std loads a plugin when it first needs it, also from a thread that extracts.
0.6.3 changes no stream, ZPAQL or codec either: a JPEG-LS file that ends with no EOI
is refused when parsed (pjals and pjalsx took it, then could not give it back, so -sa
sent it to -m after trying), the repair of damaged JPEGs no longer takes minutes, the
Windows heap fails cleanly when memory runs out, and 32-bit x86 builds the C part
with -march=i686 (the same bits, without SSE2). 0.6.4, the fixes of an audit, changes
no stream, ZPAQL or codec either: pjall's H counts the bands of a big lossless JPEG (it
could ask for too short an H), pjax and pjax7 refuse in detect a part with more scans
than MAXSCANS, and detect's verdict is kept by size and BLAKE3, so compress finds it
even when zpaq-std's fragment list follows the EOI. 0.7.0 adds the o codecs (pjalso,
pjallo, pjalsxo and their z, pjalszo, pjallzo, pjalsxzo): pjals, pjall and pjalsx with
the same streams and a ZPAQL compiled with zpaqlc's opt=2 (pas/plugin/ozpaql.inc), half
the size and over twice as fast in any zpaq; they take the place of pjall, pjals and
pjalsx in -sa, which stay in the plugin, to read. 0.8.0 adds the 8 codecs (pja78, pjax78,
pjall8, pjals8, pjalsx8 and their z, pja7z8, pjax7z8, pjallz8, pjalsz8, pjalsxz8): the
same codecs and streams once more, every decoder -sa uses compiled with zpaqlc's opt=3
(pas/plugin/v8zpaql.inc), 3 to 8% smaller and a little faster; they take the place of
pja7, pjax7 and the o codecs in -sa, which all stay in the plugin, to read. 0.9.0
freezes codecs 0 to 29 (names, streams, ZPAQL; PJA's doc/STABILITY.md) and only caps
PATCH's sizes; 0.9.5 is faster with the same bytes and brings PJA's JPEG 2000 sources
(pjaj2k*.pas and .c, pjathread.pas, pjastage.pas); 0.9.6 adds codec 30, pja2k: the
JPEG 2000 family (JP2, JPX, JPM, MJ2, codestreams) as stream version 8, codestream
modes 0 and 1, with a ZPAQL decoder (pas/plugin/j2kzpaql.inc, 51,521 bytes, comp 0 0
$3 $4 0, both from the query); HTJ2K stays as bytes. It is frozen too. 0.9.7 changes
only PJA's command (and the version in pjacodec.pas): the plugin is 0.9.6's. 0.9.8
leaves 16 bytes after each block of the Windows DLL's heap (pas/pjaheap.pas): FreePascal's
i386 code may read 2 bytes past an array of Word, and a block that ended where the
committed memory ended made an access violation (seen on Windows XP); no codec changes. 0.9.9 is for zpaq-std
2.9.0's +rcmd: each detect answers 2 for a file of its format that it does not take, and each
codec's card has fallback_ma and fallback_m, the methods it recommends for those files (measured
in PJA's doc/CODEC.md); and its BLAKE3 comes from pBLAKE3 v0.2.0 (pas/pjablake3.pas and the new
pas/b3chunks.c, built by pas/build_c.sh). The 31 codecs, their streams and ZPAQL are 0.9.8's. Files:
the sources of its zpaq-std plugin, LICENSE (MIT), NOTICE (IJG for the arithmetic-coded
JPEG, CharLS's BSD 3-Clause for JPEG-LS, OpenJPH's BSD 2-Clause for HTJ2K) and VENDOR.md (what it is and how it builds).

Stable in zpaq-std since 2.6.0.
zpaq-std's codecs for specific formats, -sa: PJA's family, one plugin with six
codecs: pjax78 (JPEG that needs PJA's stream version 6: MPO and Ultra HDR, 12 bits, DNL,
DRI without RST), pja78 (JPEG), pjall8 (lossless JPEG), pjals8 (JPEG-LS), pjalsx8
(JPEG-LS with subsampled components) and pja2k (JPEG 2000). -sa and -sa:pja use the
six, in that order. Free Pascal: by the project's rule, a codec in
Rust or Free Pascal is built only as a plugin (codecs/pja.dll or pja.so, in the extra-codecs
download), never linked into zpaq-std itself. Every block carries the codec's ZPAQL
decoder (pas/plugin/pjazpaql.inc, pjaxzpaql.inc, pjallzpaql.inc, pjalszpaql.inc,
pjalsxzpaql.inc, lzzpaql.inc for the z codecs, v7zpaql.inc for pja7, pjax7, pja7z
and pjax7z, ozpaql.inc, v8zpaql.inc and j2kzpaql.inc), so any zpaq extracts it without
the plugin; those programs are frozen under these codec names.
Do not patch these files here: send changes to the PJA repository.
