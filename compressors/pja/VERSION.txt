PJA 0.6.3 (tag v0.6.3, commit fdcfbc9), https://github.com/YadeWira/PJA,
from the vendor tarball pja-0.6.3-zpaqstd.tar.gz (sha256
eacc0759485670e6b04a1886c0edca53f5e9139b888f416ada91e519d9971e62), copied unmodified.
For the plugin, 0.3.0 frees each coding thread's model tables when the thread ends
(they leaked, and ran out of memory on 32 bits), and 0.4.0 adds the five z codecs
(pjaz, pjalsz, pjaxz, pjallz, pjalsxz): the ZPAQL of each base codec with zpaq's
level 1 LZ77 expander in front (pas/plugin/lzzpaql.inc). -sa uses one for a group
when it takes fewer bytes; they are never used by themselves. 0.5.1: pjax's detect
measures the big MPOs right (they go to pjax), the detects share one check of the
JPEG, and zpaqstd_threads_v1 (zpaq-std's -t) gives each call threads for its bands.
0.5.2 and 0.5.3 change PJA's command and libpja (a scan cut short is repaired); for
the plugin only pjacodec.pas changes (that repair, and its own check's output cap),
and its codecs write the bytes of 0.5.1. 0.6.0 adds PJA's stream v7: pja7 and pjax7
(and their z, pja7z and pjax7z), a better model with smaller, faster decoders (about
35 KB), which take the place of pja and pjax in -sa; those stay in the plugin, to read
the archives made with them. Stream v7's model is in C (pjav7c.c, pjasysc.c, built by
pas/build_c.sh and linked by fpc). 0.6.2 changes no stream, ZPAQL or codec: on Windows
the plugin takes its memory from the process heap (pas/pjaheap.pas), since FreePascal
3.2.2's own heap, in a DLL, deletes its lock when the thread that loaded the DLL ends,
and zpaq-std loads a plugin when it first needs it, also from a thread that extracts.
0.6.3 changes no stream, ZPAQL or codec either: a JPEG-LS file that ends with no EOI
is refused when parsed (pjals and pjalsx took it, then could not give it back, so -sa
sent it to -m after trying), the repair of damaged JPEGs no longer takes minutes, the
Windows heap fails cleanly when memory runs out, and 32-bit x86 builds the C part
with -march=i686 (the same bits, without SSE2). Files:
the sources of its zpaq-std plugin, LICENSE (MIT), NOTICE (IJG for the arithmetic-coded
JPEG, CharLS's BSD 3-Clause for JPEG-LS) and VENDOR.md (what it is and how it builds).

EXPERIMENTAL in zpaq-std, not recommended yet (-sa warns, 00737).
zpaq-std's codecs for specific formats, -sa: PJA's family, one plugin with five
codecs: pjax7 (JPEG that needs PJA's stream version 6: MPO and Ultra HDR, 12 bits, DNL,
DRI without RST), pja7 (JPEG), pjall (lossless JPEG), pjals (JPEG-LS) and pjalsx
(JPEG-LS with subsampled components). -sa and -sa:pja use the five, in that order. Free Pascal: by the project's rule, a codec in
Rust or Free Pascal is built only as a plugin (codecs/pja.dll or pja.so, in the extra-codecs
download), never linked into zpaq-std itself. Every block carries the codec's ZPAQL
decoder (pas/plugin/pjazpaql.inc, pjaxzpaql.inc, pjallzpaql.inc, pjalszpaql.inc,
pjalsxzpaql.inc, lzzpaql.inc for the z codecs, and v7zpaql.inc for pja7, pjax7, pja7z
and pjax7z), so any zpaq extracts it without the plugin; those fourteen programs are
frozen under these codec names.
Do not patch these files here: send changes to the PJA repository.
