sylz (format v2) and sylzec (format v3), from syc v0.5.4 (tag v0.5.4, commit b161b8c, 2026-10-29),
https://github.com/YadeWira/syc. v0.5.4 changes only plugin/sylz_zpaqstd.pas: on macOS it exports
its entry points with Darwin's leading underscore, so dlsym finds them; elsewhere the
plugin is byte for byte v0.5.3's. v0.5.2 and v0.5.3 change only src/sylzc.c for zpaq-std: it builds
with clang (__builtin_shufflevector) and, on 32-bit targets other than Windows, counts
with two 32-bit ctz instead of a 64-bit one that gcc -m32 could turn into a call to
libgcc's __ctzdi2 (Free Pascal does not link libgcc). Same bytes as v0.5.1.
Before: syc v0.5.1 (tag v0.5.1, commit afb6252, 2026-10-29). v0.5.1 makes 32-bit builds hash as 64-bit ones do
(HashFast at levels 0-1, MidHashLong at levels 2-3, which are sylzec's 0-1), so x86 and
x64 write the same bytes at every level; 64-bit output is v0.4.2's. Formats v2 and v3
unchanged. Before: syc v0.4.2 (tag v0.4.2, commit d2f9632, 2026-10-24; a pre-release). MIT, see LICENSE. Files copied unmodified:
src/sylz.pas, src/sylzhuf.pas, src/sylzc.c (C fast paths, linked into the plugins; built
freestanding with the target's gcc), plugin/sylz_zpaqstd.pas (the plugin adapter: ONE file,
codecs/sylz, with both codecs through zpaqstd_codecs_v1; zpaqstd_codec_v1 still gives sylz,
so zpaq-std 1.7.0 and earlier load it as before) and plugin/zs_codec.inc. syc 0.3.0 to 0.4.1
had sylzec in a file of its own, codecs/sylzec, which zpaq-std still loads if sylz has not it.
sylzec writes sylz format v3 (frozen at syc v0.2.14: Huffman-coded literals), or a plain
v2 block when v3 is not smaller; its blocks carry ZPAQSYLZ3 (compressors/zpaqsylz3).
syc 0.2.14 to 0.4.2 write sylz's very bytes of 0.2.10, and sylzec's of 0.3.0.
syc 0.2.11 to 0.2.13 write the very bytes of 0.2.10 at every level: only faster, and the
32-bit x86 decoder picks SSE2 or plain i686 at run time, so it runs on any x86.

Free Pascal: by the project's rule, a codec in Rust or Free Pascal is built only as a
plugin (codecs/sylz.dll or sylz.so), never linked into zpaq-std itself. Its blocks
carry ZPAQSYLZ (compressors/zpaqsylz), so any zpaq extracts them without the plugin.
Experimental: a later sylz format gets a new decoder (ZPAQSYLZ3, tag sylz3), and
blocks written now keep theirs.
syc 0.2.9 and 0.2.10 change the encoder of levels 9 and 10 (a bt4 binary tree for the optimal
parse, 768 KiB per context); syc 0.2.8 changed the encoder of levels 4 to 8 (lz4hc's parser, with an x86-64
assembly match search; other targets use the Pascal one): format v2 and ZPAQSYLZ are
unchanged.
